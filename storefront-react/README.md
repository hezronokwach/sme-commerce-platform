# Storefront (React)

The shop customers see, at `/s/:slug` (for example `/s/mamamboga`): browse products, fill a cart.
No login. Checkout and the live order page come with the next issue.

Vite + React 19 + TypeScript 6, React Router, Vitest + Testing Library. Node 22.12+ (CI uses 24).

## Run it

The backend must be running on port 8080 (see `backend/`). Then:

```bash
npm install
npm run dev
```

Open http://localhost:5173/s/your-shop-slug. Vite passes every `/api` call on to the backend
(`vite.config.ts`), so the browser sees one address and no CORS setup is needed locally.

| Command | What it does |
| --- | --- |
| `npm run dev` | Development server with hot reload |
| `npm test` | Unit and page tests (Vitest, jsdom) |
| `npm run lint` | oxlint |
| `npm run build` | Type check (`tsc -b`), then a production build in `dist/` |
| `npm run generate-api` | Rebuilds `src/api/schema.d.ts` from `docs/api/openapi.json` |

## The API client

`src/api/schema.d.ts` is generated by openapi-typescript and only holds types. `src/api/client.ts`
uses openapi-fetch with those types, so a wrong path or a renamed field fails `npm run build`.
After the backend's API changes (and `OpenApiTests` has rewritten `docs/api/openapi.json`), run
`npm run generate-api` and commit the result. CI fails if they don't match.

TypeScript stays on 6.x: openapi-typescript uses the TypeScript JavaScript API, which TypeScript 7
(the Go rewrite) doesn't have. `overrides` in `package.json` lets it use our TypeScript 6 even though
it declares TypeScript 5 as its peer.

## Where things are

| Folder | Contents |
| --- | --- |
| `src/shop/` | `ShopLayout` (loads the shop, "Shop not found", the shop's colours), product list, product page |
| `src/cart/` | The cart: logic and storage (`cart.ts`), provider, badge, "Add to cart", cart page |
| `src/api/` | Generated types and the client |

The cart is kept in `localStorage` under `cart:<shop slug>`, so two shops' carts never mix. Its
prices are only for showing: at checkout the server prices the order again.

A deployed build needs `VITE_API_BASE_URL` set to the backend's address (Vercel, a later issue).
